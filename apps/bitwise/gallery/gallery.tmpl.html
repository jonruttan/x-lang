The owl stamped in every x source header, set in Roboto Mono exactly as it is on jrexpr.ca. Type a name and the owl stays the owl while the field it sits on is decided by the name's SHA-256. A project with a mascot, a logo colour or an idiom of its own wears it as a costume.

The flock

Every project in the x workspace, as its own bird. Pick one to put it on the plate.

How a bird is seeded

The owl itself is never generated. It is the five glyphs from the source headers, set from Roboto Mono's outlines so it is identical on every machine, with the eyes taking the project's accent.

Costumes are data, in langs.xon. A costumed owl wears the v beak and carries its project's logo on its belly: a C for the C projects, λ for the Schemes, {+} for sweet-expressions, /./ for grep, vau for Kernel. Ferris keeps his pincers, V V. A logo colour replaces the hashed hue in the field, and x-python's eyes take the two snakes' colours. Every project also gets a one-line reference in its own language on the banner.

The name is hashed once. The first ten bytes of the digest are read off in order, each one settling a single trait. Bytes 10 to 31 are unused, kept for later.

The field is a bit of a bitwise function, sampled on a grid: cell (x, y) is lit when the chosen bit of f(x, y) is set. If a name lands on a near-empty or near-solid field, the bit advances, then the operator, until it reads as a texture. That walk is deterministic, so it is still the name that decides.

This page is the browser twin of apps/bitwise, the x-lang program that owns the design; both compute the same integer geometry and produce byte-identical SVG, and the spec suite holds the digests they must agree on. Render every project from an x-lang checkout:

x -l bitwise -- --all --png

An edited generator is a different flock. Re-render everything rather than touching an SVG by hand; the parity test keeps the page and the CLI drawing the same picture.
